# Honest labelled traffic corpus

Generates a labelled HTTP corpus where **labels come from capture provenance, never from
inspecting payload content with our detection rules** (D9–D14). This replaces the
silver-labelling ring (`rules/base_rules.json` → labels → NLP learns the rules) and the
synthetic `tests/owasp_top_10_smoke.py` training source that made lab metrics 0.99 while
real traffic gave ~100 % FPR.

Real here: the requests (real HTTP to a real running app), the attack payloads
(sqlmap / ffuf+SecLists / nuclei / hydra / curated real payloads), and the labels
(independent of our detector). Synthetic here: only the testbed environment and the
scripted benign workload — declared as such (D13).

## The provenance invariant

1. A mitmproxy reverse-proxy addon (`mitm_addon/capture_addon.py`) records every flow with
   the client peer IP the proxy sees. It assigns **no labels** and inspects **no content**.
2. Each generator (benign or attack) runs from a **distinct static IP** on the
   `corpus_net` docker network and writes a **campaign manifest** (family, tool, src_ip,
   time window).
3. `label/labeller.py` assigns `label / attack_family / attack_tool / label_source` purely
   by matching a flow's `(src_ip, timestamp)` into a campaign window. It imports only stdlib
   + pandas — no `rules/`, no `nlp_infer`, no `re` (asserted by AST in the verifier).
   `session_id` comes from the JWT `sub` for authenticated flows, else `app:ip:<src>`.

If a labelling step ever needs to look at a payload, that reintroduces the circularity this
corpus removes — so it never does.

## Layout

```
common/schema.py        unified schema (one row per HTTP transaction)
common/manifest.py      campaign-manifest writer/reader (the only label source)
common/uas.py           shared realistic User-Agent pool (UA is not a label tell)
mitm_addon/             capture addon -> raw JSONL, no labels
benign/                 vampi_driver.py, crapi_driver.py (scripted legitimate flows)
attacks/                run_tool.py (ffuf/nuclei/hydra/sqlmap wrapper), custom_inject.py,
                        behavioural.py, crapi_context.py, run_sqlmap.py, payloads.py
label/labeller.py       provenance-only labeller
ingest/                 zanbil_ingest.py, srbh_ingest.py (external held-out sets)
split/split_corpus.py   split by session, never by row
Dockerfile.generator    benign driver + sqlmap image
Dockerfile.attacker     ffuf + nuclei + hydra + sqlmap + python
docker-compose.phase1.yaml / phase2.yaml
run_phase1.sh / run_phase2.sh   reproducible entrypoints
verify_phase1.py / verify_phase2.py
```

## Tool diversity (anti-fingerprint)

Every content family is generated by **≥ 2 independent tools** so a detector cannot learn
the tool's fingerprint instead of the attack. `custom_inject.py` uses payloads **distinct
from** the SecLists lists ffuf uses, so the cross-tool holdout (train on one tool, test on
the held-out tool) does not leak. `attack_tool` is recorded faithfully per row. All tools
draw User-Agents from the shared realistic pool (sqlmap `--random-agent`) so UA is not a
tell. See `../docs/owasp_coverage.md` for the family → OWASP → detector map.

## Running

```bash
bash corpus/run_phase1.sh    # small validation: VAmPI + mitmproxy + sqlmap
bash corpus/run_phase2.sh    # full: VAmPI + crAPI + full tool suite + external ingestion
```

Requires Docker, the pinned images (digests in the compose files / run manifest), SecLists
at `~/.cache/corpus-tools/SecLists`, and crAPI running for Phase 2. Labelling/verification
use `python3.13` (needs pandas + pyarrow). Captured parquet/JSONL is gitignored under
`data/corpus/` and `data/external/`; the reproducibility manifests are committed under
`docs/corpus/`.

## What the ML is and isn't expected to catch

`bola_idor`, `mass_assignment`, `business_logic_abuse` are **context** families: each
request looks legitimate (valid token, well-formed body); only application authorization
context reveals the abuse. They are generated and labelled from script intent to provide
ground truth for the context/agent track and to measure the honest ceiling — the
per-request ML is not expected to catch them. Stating otherwise would be the inflated
result this corpus exists to avoid.
